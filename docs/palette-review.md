## 2. 诊断：第一版为什么「像没改」

底色只要还停在 `#0a0a0c ~ #181512` 这个近黑区间，色相就被吞掉了：青瓷绿、靛蓝与原来的中性黑在屏幕上几乎是同一个颜色，
「换底 + 换主色」实际只让人看到按钮颜色变了。所谓「AI 味」的三个真实来源也都不在色相上：

1. **明度结构单一**：整屏 `#0a → #24`，只有约 8% 的明度跨度，所有面板糊成一块；
2. **霓虹级强调色 + 发光**：`#ff6d4f` 叠加 `0 12px 32px` 橙色光晕；
3. **彩色雾**：背景两层朱砂／蓝的径向光。

结论：必须改明度结构（把底推到能看见色相的明度、并分出五层），而不是换色号。

### 三处结构性动作

1. **明度结构**：`#1e1506 → #493819` 五层陈褐逐层亮起；顶部一层极淡灯光，四角压暗，像旧物标本的拍摄台。
2. **主次反转**：主操作从「暗红实心 + 米白字」改成「琥珀实心 + 墨字」——屏上最亮的一块就是下一步。
3. **语义分层**：琥珀只做「当前 / 主操作 / 强调」，错误另用砖红 `--error` `#e2a07f`；通过铜绿、待办旧金、信息灰青。
   错误色是独立令牌，视图里的错误/失败/告警都用令牌或 `color-mix()` 派生（例外只剩遮罩用的纯黑与纸面高光白）。

## 7. 遗留问题与风险

- 四角暗角叠在固定层 `.ambient` 上，滚动时相对视口不动；超宽屏（>2000px）边缘是否压得太狠未复核。
- 只在 Chrome 验证；Safari / Firefox 与完整屏幕阅读器走查未做。颜色依赖 `color-mix()`（Chrome 111+ / Safari 16.2+ / Firefox 113+）。
- 设置页底部粘性保存条仍会盖住其下方滚过的说明文字（既有观感问题，与配色无关，未在本批改）。
- 潜在对比度：`--text-4` 在最亮面板 `--bg-4` 上为 4.00:1，检查脚本对「极弱标注」按 3:1 判，但目前 12–13.5px 的元信息只落在
  `--bg-1/2` 上；若以后把元信息放到 `--bg-4`，需要重新核。禁用态按钮整体 `opacity: .42`，WCAG 允许，但禁用主按钮仍是
  一块淡琥珀，观感上像可点——如需更稳，应加专门的禁用令牌而不是调透明度。
- 本批没有重拍「对比」截图：现有素材只有原件与规范输入，工作台对这两个版本如实提示「没有可对比的另一个版本」；
  等有真实线稿/透明 PNG 产物后再补。
- 彩色光晕已移除，但主操作、印章与滑柄仍是高饱和琥珀；若后续要更「文物感」，应改的是材质与明度差，而不是再加滤镜。
