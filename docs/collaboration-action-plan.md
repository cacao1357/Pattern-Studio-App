## 1. 目标与方向

以当前 Pattern Studio 为起点，完成“单张平面纹样图片 → 保真透明 PNG → 可编辑 SVG”的可靠处理闭环。聚焦复杂背景、近色背景、细线、孔洞及多色边界，减少人工步骤，同时保留必要的人工修正能力。

遵循《平面纹样智能提取项目行动纲领》的产品闭环、分割保真、独立矢量化、可追溯资产和固定样本验收方向。按本次讨论作以下调整：

- 按阶段及出口条件推进，不设周数和日期承诺。
- 当前只使用云端图像模型及现有本地图像算法，不安排自有模型训练、云 GPU 或新供应商接入。
- 三人各负责完整功能链，负责人另外承担整合与兜底。
- 保持现有前端，补齐功能对接和设置界面，视觉美化后置。（2026-11-10：新版前端已完成并接入本机服务，旧前端文件原地保留、通过 `/legacy/` 只读对照；接入提交 `016197b` 已于 2026-11-11 合并 `main`，见 [前端接入说明](frontend-integration.md)。）
- 在现有后端实现轻量工作流，不引入 ComfyUI 作为运行依赖，也不自研节点拖拽编辑器。

保留未来模型替换的接口边界即可，不为后续训练预建完整平台。纲领中的训练、权重交付和按周里程碑不属于本轮验收。

## 3. 范围与保真原则

### 本轮交付

- 单图、单个主要平面纹样的提取。
- 默认一次云端拆分后，自动选择与合成图层，生成透明 PNG 和可编辑 SVG。
- 有歧义时进行必要的图层确认或蒙版修正，确认后继续流程。
- 可追溯的工作流、提示词、模型及参数记录。
- 设置界面、局部重跑、失败恢复、结果预览与导出。
- 固定样本质量报告及明确的支持范围。

### 后置内容

批量处理、复杂实物透视、严重遮挡补全、连续纹样拼接、新增复杂重绘、模型训练、共享服务、多用户权限、通用工作流平台及前端美化。

### 质量原则

优先忠实原图，保留主体数量、轮廓、相对位置、颜色关系、细线和孔洞。生成修复必须由用户明确选择，独立保存候选，不覆盖原图或已接受结果，也不混入保真提取的成功率。

分别统计自动完成、人工修正后完成、失败。不得通过重新命名或降低标准掩盖失败。

## 4. 轻量工作流方案

### 默认处理链

原图 → 一次云端图层拆分 → 输出检查 → 自动选层或人工确认 → 合成透明 PNG → 本地矢量化 → 预览与导出。

这里的步骤是后台职责，不是用户必须逐项点击的界面。一个用户操作可以驱动完整链路；一个云端请求可能产生多张图层，不能按“一次请求等于一张图费用”估算成本。

### 可选分支

- 无法明确选择主体图层时暂停，提供选层确认，随后继续。
- 用户发现提取缺陷时进入蒙版修正，再重跑受影响的下游步骤。
- 现有清晰化能力保持可跳过；额外云端清晰化或修复只有在实测证明收益后才加入对应预设。
- 不设自动无限重试，不默认串行多次生图。

自动选层不能只依赖面积最大或合并所有透明层。B 应使用图层信息及开发样例建立可解释规则；无法明确处理的情况保留确认入口。基础检查可以识别空产物、尺寸或格式异常，但不得据此宣称几何保真已经验证。

### 首期工作流能力

只支持项目所需的预设步骤、有限条件分支和人工确认点。复用现有任务与存储设施，不先建设通用 DAG 引擎。

每次运行冻结并记录：

- 工作流标识及版本、输入资产标识。
- 提示词标识、版本及实际文本或可追溯快照。
- 模型或接入点、有效参数、图层选择及处理参数。
- 步骤状态、产物引用、父子关系、开始结束时间。
- 云端请求标识、已知用量、费用估算依据和失败信息。

配置中只引用凭据，不包含密钥。分享工作流和实验记录时不得携带密钥。

### 重跑与恢复

- 修改选层或蒙版：复用云端结果，只重跑合成及下游。
- 修改矢量参数：复用透明 PNG，只重跑矢量化。
- 修改提示词、模型或输入：创建新的云端运行及产物，不覆盖旧结果。
- 云端超时或网络中断：记录“结果不确定”，不能自动视为未计费或立即重发。
- 本地步骤失败：保留成功产物，从明确的失败步骤恢复。
- 取消本地任务不等于云端撤销或退费；状态展示应反映这一边界。

## 5. 提示词设计与实验

### 主模板

首期集中优化“保真纹样拆分”主模板，不为每个本地步骤新增提示词。当前接口使用 prompt 字段，项目中的“系统提示词”指服务端维护的任务模板，不假设存在独立 system 角色。

模板应表达目标主体、完整性、需要保留的结构与颜色、背景拆分意图，以及不补全、不重绘的边界。尽量减少无必要的图层碎分。图片中的文字属于待处理内容，不作为流程指令。

输出格式、尺寸和拆分开关由 API 参数管理。提示词不是精确保真的保证，必须以实测结果判断。

以下只作为开发起点，不是已经验证的默认模板：

> 将输入图片中的主要平面纹样与背景分离。完整保留纹样的原有轮廓、内部线条、孔洞、颜色和元素相对位置，不增加、删除、补全或重新设计纹样。围绕完整纹样主体与背景进行拆分，避免无必要地把同一纹样拆成大量碎层，不将背景当作纹样输出。

具体表述由 B 根据目标素材、接口行为和实验结果调整；模型原生拆分可能仍输出多个主体层，由后续合成处理。

### 优化方法

1. 先比较当前提示词与改进后的单次拆分模板。
2. 使用开发样例，尽量每次只改变一类因素；记录所有有效参数，不能只记录提示词。
3. 对关键难例做适量重复调用，检查结果波动；不承诺相同参数一定生成相同图片。
4. 同时评价透明 PNG、SVG 和人工操作量，不单看生成图是否漂亮。
5. 只有单次流程的明确失败类型，才进入额外云端步骤的对照实验。
6. 改进有证据才替换默认版本，保留上一版本和回退入口。

每轮实验先明确样例数量、最大请求数或费用上限，使用现有费用门禁。具体额度在真实调用前确认，本方案不构成无限付费实验授权。

普通设置页暂不开放任意编辑模板；开发通过实验配置使用候选版本，运行记录能够追溯实际使用的模板。

## 6. 三人分工与文件责任

三人包含负责人本人。工作量按完整交付包平衡，不要求任务条数相等；负责人承担公共链路和整合，因此不兼任 B、C 的主要算法实现。

| 成员 | 独立主责 | 交付终点 |
| --- | --- | --- |
| A：负责人 | 配置与设置页、公共云端适配接口、轻量流程编排、状态和恢复、最终集成 | 可以安全配置并一键执行、定位错误及局部重跑 |
| B：提取负责人 | 主提示词与实验、云端拆分策略、图层选择、合成与蒙版修正、相应前端对接 | 从原图得到可追溯的透明 PNG，并对提取质量负责 |
| C：矢量负责人 | 颜色归并、轮廓和路径简化、碎片控制、矢量预览导出、相应前端对接 | 从透明 PNG 得到可编辑 SVG，并对矢量质量负责 |

### 具体边界

- A 维护公共配置、调用契约、工作流编排和共享入口；B 提交提示词及策略，避免与 A 同时修改适配器。
- B 主要负责提取、选层、合成和修正相关服务及自己的验证资料。
- C 主要负责矢量服务、导出行为和自己的验证资料。
- 现有 frontend/workbench.js、index.html 等共享文件按功能区和合入顺序协调；不要三人同时修改同一区域。确有必要时再做小范围模块拆分，不为分工重构整个前端。
- B 负责执行并记录提示词实验；C 评价其下游矢量影响；A 组织阶段验收。
- 三人共同确定样本和判定标准；每人对自己的实现、自测、说明和缺陷修复负责。

前端主要实现如委派 Agent，遵循项目既定 DSH 策略；非前端辅助工作不委派 DSH。外部工具调用不能替代成员的审查责任。

### 交接契约

先记录现有字段和数据结构，再补齐缺失项，避免平行创建第二套任务或资产系统。

| 交接 | 最小内容 |
| --- | --- |
| A → B/C | 调用与任务接口、状态、错误格式、配置读取边界、模拟响应 |
| B → C | 透明 PNG／资产引用、画布尺寸与坐标约定、透明度处理、来源及人工修正记录 |
| B → A | 提取执行结果、候选层、等待确认的原因、可恢复步骤与产物引用 |
| C → A | SVG／资产引用、有效参数、验证结果、失败原因及来源 PNG |

不得无声更换画布尺寸、裁切坐标或透明度语义。B 尚未完成时，C 使用固定透明 PNG 独立开发；A 接口尚未完成时，B/C 使用约定样例和模拟响应推进。

## 8. 验收与测试

### 固定样本

固定验收集为 30 张，覆盖干净背景、复杂背景、近色、细线／孔洞、多色五类。可先按每类约 6 张组织，再按素材实际情况确认分类。开发样例单独维护；原图和许可信息按既有资源管理约定存放，不把私有素材或生成大文件直接提交 Git。

固定验收集不用于日常提示词调优。若依据其失败样例做针对性修改，记录这一事实，并补充未参与调试的样例复核。

### 判定维度

| 维度 | 判定要求 |
| --- | --- |
| 链路成功 | 至少 27/30 张生成可打开的 PNG 和 SVG；只代表运行门槛 |
| 提取保真 | 主体完整，关键线条、孔洞、元素关系和颜色无明显错误 |
| 矢量质量 | 关键轮廓保留、无严重碎片化，可选择及修改路径，不是仅嵌入位图 |
| 人工成本 | 分别记录自动、选层确认、蒙版修正等参与情况 |
| 稳定性 | 关键难例的重复结果可接受，无静默覆盖或重复付费行为 |
| 效率与费用 | 记录端到端耗时、请求数、输出数量和可获得的实际／估算费用，明确区分 |

质量通过率、关键类别底线和可接受人工操作量在阶段一基线后确认，最终验收不得临时降低。关键结构错误不能被总体平均值掩盖。

### 测试范围

- 文档和配置说明：T0 链接、路径和格式检查。
- 图层、提示词组装、矢量参数的局部变化：T1/T2 定向行为验证。
- 工作流、设置持久化和任务恢复：T3 相关集成验证，覆盖失败、重启或并发边界。
- 真实云端图像质量：TX，在批准的实验额度内运行。
- 不默认全量回归；发布或项目强制检查需要时再执行 T4。

关键异常包括无效图片、超限输入、缺失或无效密钥、限流、超时、错误图层格式、本地矢量化失败和恢复。用可控模拟验证异常，不为制造故障消耗真实付费调用。

## 9. 设置与本地使用

三人各自运行应用、各自保存密钥，通过 Git 协作代码，不共享运行时配置和素材数据库。

首期设置包含 API Key 配置／替换／清除、现有服务的模型或接入点、付费开关、现有费用门禁所需参数和状态提示。复用当前配置机制，并明确保存后立即生效或需要重启，避免“保存成功但调用仍使用旧值”。

密钥由后端保存，不返回明文、不写前端持久化存储、不进入日志、工作流导出或 Git。配置写入需验证、避免部分写入，失败时保留原有效配置。

配置检查与付费试调用分开。界面如展示预算，必须准确说明是预估门禁还是可保证的硬限制，不夸大控制能力。

## 10. 协作、阻塞与范围控制

- 从现有目录和代码约定出发，只增加任务确需的文件；不顺带重构和清理无关内容。
